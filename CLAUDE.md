# RCam

macOS menu-bar RTSP camera viewer (app + camera-extension system extension + `rcamcli`).

## Building and running

- `scripts/build.sh` is the canonical build: it stamps `CFBundleVersion`, runs `xcodegen generate`, builds the RCam and rcamcli schemes, and installs the app to `/Applications/RCam.app`. A bare `xcodebuild` compiles but does **not** update the installed app — to see a change in the running app, run `scripts/build.sh` and relaunch RCam.
- The project file is generated by XcodeGen from `project.yml`; edit `project.yml`, not `RCam.xcodeproj`.
- `scripts/build-ffmpeg.sh` rebuilds the vendored FFmpeg in `vendor/`; `scripts/testrig.sh start` spins up a local RTSP test rig (mediamtx + synthetic streams at `rtsp://127.0.0.1:8554/test` and `/test-sub`).
- `scripts/build.sh` installs the app but does **not** activate the camera system extension — that happens when RCam next launches. After a build that touched `RCamExtension/`, launch RCam and confirm `systemextensionsctl list` shows the new version `[activated enabled]` with no sibling in `terminated waiting to uninstall on reboot`, and only then reboot. Rebooting straight after the build drains the wrong generation and costs a second reboot; `systemextensionsctl list` alone looks healthy in the broken case.

## Releasing

- Releases are cut by `.github/workflows/release.yml` on a `v*` tag push. To ship: bump `MARKETING_VERSION` in `project.yml`, move the `## [Unreleased]` notes in `CHANGELOG.md` into a dated `## [X.Y.Z] - YYYY-MM-DD` section, commit to `main`, then `git tag vX.Y.Z && git push github vX.Y.Z` and approve the `release` environment deployment. `scripts/release.sh` fails unless the tag equals `v$MARKETING_VERSION` and the changelog has a matching section (that section becomes the release notes and the Sparkle item's description).
- `scripts/release.sh` runs the same build locally (Developer ID signing, notarization via `NOTARY_PROFILE`, DMG, Sparkle signing from the login keychain; env vars are documented at the top of the script). It never installs or publishes anything. `scripts/release.sh --unsigned` needs no certificates or Apple account and still produces the DMG and every artifact in `build/release/`, so use it to smoke-test script changes.
- The Sparkle appcast lives on the GitHub Pages site (`site/`, served at `https://rcam.strawdynamics.com/appcast.xml`). The workflow fetches the live appcast, prepends the new item with `scripts/appcast-merge.sh`, and redeploys `site/`; the committed `site/appcast.xml` is only the seed for the very first release, so don't hand-edit it expecting the live feed to change.
